工事管理システム
構築ガイド

MCP・Terraform・GitHub Actions を組み合わせ、Apache上で動く工事管理システムをゼロから自動構築・自動保守するための完全ガイドです。

1全体アーキテクチャ

システム全体は「コードを書いてpushするだけで本番環境まで自動反映される」フローで動きます。

3MCPの活用

MCP（Model Context Protocol）はClaude Codeが外部サービスを直接操作するためのプロトコルです。本プロジェクトでは GitHub MCP を中心に活用します。

4要件定義MDの書き方

要件定義をMarkdownで書いておくと、Claude Codeが仕様を理解しやすくなり、コード生成の精度が上がります。requirements/requirements.md に以下の構成で書きます。

# 工事管理システム 要件定義

## 1. 目的・背景
- 紙ベースの工事台帳をデジタル化する
- 現場・事務所どちらからでもアクセス可能にする

## 2. ユーザー・権限
| ロール     | できること                              |
|-----------|----------------------------------------|
| 管理者    | 全操作・ユーザー管理                     |
| 現場監督  | 工事・日報の登録・編集                   |
| 作業員    | 日報の参照のみ                           |

## 3. 機能要件
### 3.1 工事管理
- [ ] 工事一覧表示（検索・絞り込み付き）
- [ ] 工事詳細登録（案件名・場所・工期・担当者）
- [ ] 進捗ステータス管理（予定/施工中/完了/中断）

### 3.2 工程管理
- [ ] ガントチャート形式の工程表示
- [ ] マイルストーン設定

### 3.3 日報管理
- [ ] 日報入力（作業内容・人員・天気・特記事項）
- [ ] PDF出力

## 4. 非機能要件
- レスポンス: 3秒以内
- 可用性: 99.9%（月次ダウンタイム 43分以内）
- セキュリティ: HTTPS必須・SQLインジェクション対策

## 5. 画面一覧
- ダッシュボード
- 工事一覧 / 詳細 / 登録・編集
- 作業員一覧 / 詳細
- 日報一覧 / 入力
- 設定

## 6. API仕様（将来）
GET  /api/projects        # 工事一覧
POST /api/projects        # 工事登録
GET  /api/projects/:id    # 工事詳細
PUT  /api/projects/:id    # 工事更新
requirements.md
📝 コツ: チェックボックス形式（- [ ]）で書くと、実装進捗をそのままGitHubのIssueと連携できます。

6Terraform — インフラをコードで管理

Terraformを使うとAWSリソースをコードとして管理でき、削除・再構築が何度でも同じ状態で再現できます。

main.tf — EC2 + VPC + Security Group

# terraform/main.tf

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  # Stateファイルをs3で管理（チーム開発に必須）
  backend "s3" {
    bucket = "construction-mgmt-tfstate"
    key    = "prod/terraform.tfstate"
    region = "ap-northeast-1"
  }
}

provider "aws" {
  region = var.aws_region
}

# --- VPC ---
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags = { Name = "construction-mgmt-vpc" }
}

resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  map_public_ip_on_launch = true
}

# --- Security Group ---
resource "aws_security_group" "web" {
  name   = "construction-mgmt-sg"
  vpc_id = aws_vpc.main.id

  ingress { from_port=80  to_port=80  protocol="tcp" cidr_blocks=["0.0.0.0/0"] }
  ingress { from_port=443 to_port=443 protocol="tcp" cidr_blocks=["0.0.0.0/0"] }
  ingress { from_port=22  to_port=22  protocol="tcp" cidr_blocks=[var.my_ip] }
  egress  { from_port=0   to_port=0   protocol="-1"  cidr_blocks=["0.0.0.0/0"] }
}

# --- EC2 Instance ---
resource "aws_instance" "web" {
  ami                    = data.aws_ami.al2023.id
  instance_type          = var.instance_type
  subnet_id              = aws_subnet.public.id
  vpc_security_group_ids = [aws_security_group.web.id]
  key_name               = var.key_name
  user_data              = file("user_data.sh")
  tags = { Name = "construction-mgmt-web" }
}

# 最新のAmazon Linux 2023 AMIを自動取得
data "aws_ami" "al2023" {
  most_recent = true
  owners      = ["amazon"]
  filter { name="name"   values=["al2023-ami-*-x86_64"] }
  filter { name="state"  values=["available"] }
}main.tf

user_data.sh — Apacheを自動インストール

#!/bin/bash
# terraform/user_data.sh
# EC2起動時に1回だけ実行される初期化スクリプト

set -e

# パッケージ更新 & Apache + PHP インストール
dnf update -y
dnf install -y httpd php php-mysqlnd php-json php-mbstring

# Apache 起動・自動起動設定
systemctl enable --now httpd

# DocumentRoot の権限設定
chown -R apache:apache /var/www/html
chmod -R 755 /var/www/html

# mod_rewrite 有効化 (.htaccess 対応)
sed -i 's/AllowOverride None/AllowOverride All/' /etc/httpd/conf/httpd.conf
systemctl restart httpd

# MySQL クライアント
dnf install -y mariadb105user_data.sh

8CI/CD — GitHub Actions

mainブランチへのpushで自動的に「Terraform → Apacheへデプロイ」が走ります。

# .github/workflows/deploy.yml
name: Deploy to AWS

on:
  push:
    branches: [main]

jobs:
  # ─── Job 1: Terraform でインフラを管理 ───
  terraform:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3

      - name: Terraform Init
        run: terraform -chdir=terraform init
        env:
          AWS_ACCESS_KEY_ID:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}

      - name: Terraform Plan
        run: terraform -chdir=terraform plan -out=tfplan
        env:
          AWS_ACCESS_KEY_ID:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}

      - name: Terraform Apply
        run: terraform -chdir=terraform apply -auto-approve tfplan
        env:
          AWS_ACCESS_KEY_ID:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}

  # ─── Job 2: アプリをEC2にデプロイ ───
  deploy:
    needs: terraform  # Terraform完了後に実行
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Deploy app via rsync
        uses: burnett01/rsync-deployments@6.0.0
        with:
          switches: -avz --delete
          path:     app/
          remote_path: /var/www/html/construction-mgmt/app/
          remote_host: ${{ secrets.EC2_HOST }}
          remote_user: ec2-user
          remote_key:  ${{ secrets.EC2_SSH_KEY }}deploy.yml

9保守の自動化

ログ監視 + アラート

CloudWatch Logsにhttpdログを送信し、5xxエラーが閾値を超えたらSNS→メール通知。Terraformで設定。

自動バックアップ

RDS自動スナップショット（毎日）+ S3へのDBダンプをCronで実行。保持期間7日。

OSパッチ自動適用

AWS Systems Manager Patch Manager を使い、毎週日曜深夜に自動パッチ適用。

依存ライブラリ自動更新

GitHub Dependabotを有効化。脆弱性のある依存パッケージのPRを自動作成。

コスト監視

AWS Budgetsで月額上限を設定。超過・予測超過で自動アラート。
